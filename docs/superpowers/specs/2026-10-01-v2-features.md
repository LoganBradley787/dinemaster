# DineMaster v2 features

Builds on `2026-09-23-dining-tracker-design.md` (read its §Ingest "Public API" for the transactions DataFrame, §Day counting, §Usage & balances). Existing metrics in `dinemaster/metrics.py` stay as they are — these features sit beside them.

## Shared rules (every module)
- Pure Python over the ingest DataFrame + `Config` (`dinemaster/config.py`, already extended: `cfg.forecast`, `cfg.max_meals_per_day`, `cfg.calendar`, `cfg.markers`, `cfg.habits`, `cfg.history`, `AwayPeriod.source`). No Streamlit imports outside `app.py`. Do not edit `config.py`/`config.toml`/`pyproject.toml`; if you need a new setting, hardcode a named module constant and report it.
- **Observed window.** Usage is only *known* for days `S..O` where `S = cfg.semester_start` and `O = freshness.observed_through(cfg, df)` (earlier of clamped as-of and export coverage). Days after `O` are unknown, never "zero-meal days". History = `S..O`; future = `O+1..E` (`E = cfg.semester_end`). Transactions before `cfg.data_cutoff` are ignored except in semester comparison.
- **Away days.** When `cfg.exclude_away` is on, `cfg.is_away(d)` days are excluded from history averages and get zero planned/forecast usage. When off, they're ordinary days.
- **Meals** per day = net ME swipes (`kind in {usage, reversal}`, −amount) + DD purchases with `dd_class == "meal"` (count a split-tender purchase once: same timestamp+description). `metrics.daily(df, cfg)` already gives per-day `me_swipes, dd_meals, dd_snacks, dd_spend, meals, me_bal, dd_bal` for `S..A`; reuse it and truncate to `O`.
- Balances: `metrics.balances(df, cfg)` → `me_left`, `dd_left`. `cfg.round_meals(dd/price)` converts DD to meals.
- Weekday numbering: Monday=0 … Sunday=6. Dates are `datetime.date`.
- Empty/short data must never crash: return empty frames / `None` fields with a short `reason` string.
- Tests: pytest, synthetic hand-built DataFrames only (never copy rows from `raw-data/`); test-first. Each module owns exactly its files (listed below) — do not touch other modules, `app.py`, `tiles.py`, or `charts.py` (import shared colors from `charts.py` if useful).
- Figure builders return `plotly.graph_objects.Figure`, live in `<module>_charts.py`, and follow `charts.py` styling (ME navy `#232D4B`, DD orange `#E57200`, gray ideal, no chart junk).
- Do not run git commands. Do not start long-running servers.

## 3. Forecast — `forecast.py`, `forecast_charts.py`, `tests/test_forecast.py`
Day-of-week-aware, recency-weighted projection with a likely range.
- `weekday_profile(df, cfg) -> pd.DataFrame` indexed 0..6 with columns: `weekday` (name), `days` (observed non-away days of that weekday), plain averages `meals_avg, me_avg, dd_meals_avg, dd_spend_avg, dd_snack_avg`, forecast rates `me_rate, dd_meal_rate, dd_spend_rate, dd_snack_rate, meals_rate`, and `share` (that weekday's fraction of a week's `meals_rate`). Forecast rates = recency-weighted mean (weight `0.5 ** (age_days / half_life_days)`, age measured back from `O`) shrunk toward the overall weighted daily mean with `prior_days` pseudo-days.
- `forecast(df, cfg) -> Forecast` with `profile`, `observed_through`, and per pot (`me`, `dd`) a `PotForecast`: `expected` (pd.Series date→expected end-of-day balance for `O..E`, starting at the current balance on `O`), `lo`/`hi` (band percentiles from `cfg.forecast.band`), `leftover_p50/lo/hi` at end of `E` (floored at 0), `prob_lasts` (share of simulations with balance > 0 after `E`), `runout_p50/lo/hi` (dates the balance hits 0, among simulations that run out on or before `E`; `None` if fewer than 5% do), `reason`. Simulation: for each future non-away day draw that weekday's usage by weighted bootstrap from observed same-weekday days (recency weights; with probability `prior/(n+prior)` draw from all observed days instead); seeded by `cfg.forecast.seed`; `cfg.forecast.simulations` runs; vectorized numpy. ME consumes swipes; DD consumes dollars (meals + snacks).
- Charts: `weekday_profile_chart(profile)` (bars per weekday: ME swipes + DD meals stacked, with observed-day counts in hover and a line/marker for DD $), `forecast_chart(pot_forecast, actual_series, cfg, title, unit)` (actual line through `O`, expected line, shaded band, semester-end line, away shading).

## 4 + 5. Daily plan & DD spend-down — `budget.py`, `tests/test_budget.py` (depends on forecast.py)
- `daily_budget(cfg, me_left, dd_left, profile, start, include_dd=True) -> pd.DataFrame` indexed by date `start..E`: `weekday, away, weight, meals` (int). Total to place `M = floor(me_left) + (round_meals(dd_left/price) if include_dd)`. Weights = profile `meals_rate` by weekday (uniform if the profile is empty/zero), 0 on away days. Integer allocation by largest remainder, capped at `cfg.max_meals_per_day` per day (redistribute overflow; if `M` exceeds capacity, fill to the cap and report the surplus in `df.attrs["surplus"]`; `df.attrs["total"] = M`). `start` is `O+1`.
- `today_line(budget, today) -> str` e.g. "2 meals today, 1 tomorrow".
- `spend_down(cfg, me_left, dd_left, profile, start) -> SpendDown`: remaining usable days `R` (`start..E`, minus away days when on) and weeks `W = R/7`; `snack_reserve` = expected snack $ over those days from profile `dd_snack_rate`; `dd_for_meals = max(0, dd_left − snack_reserve)`; `dd_meals = floor(dd_for_meals / meal_price)`; `dd_meals_per_week`, `exchanges_per_week = me_left / W`, `meals_per_day = (me_left + dd_meals) / R`, `dd_unallocated` (dollars left after whole meals), `sentence` (plain English, e.g. "Buy about 2 meals a week with dining dollars and use about 10 exchanges a week — both reach zero on Dec 18."), `reason` when `R <= 0`.

## 6. Calendar — `calendar_sync.py`, `tests/test_calendar_sync.py`
- `load_calendar(cfg, now=None) -> CalendarResult(away: list[AwayPeriod], markers: list[Marker], warnings: list[str], sources: list[str])`. Reads every `*.ics` in `cfg.calendar.ics_dir` plus each URL in `ics_urls` (fetched with urllib, cached in `cfg.calendar.cache_dir` for `cache_hours`; on fetch failure use a stale cache if present and add a warning; never raise). Uses the `icalendar` package (already installed). Considers events overlapping `[S, E]`: title matching `away_patterns` and spanning at least one full day (all-day events, or timed events ≥ 20h) → `AwayPeriod(name, start, end, enabled=True, source="calendar")` with inclusive end (ICS all-day DTEND is exclusive); title matching `marker_patterns` → `Marker`. Handle simple recurring events only if cheap; otherwise skip RRULE events and say so in a warning.
- `apply_calendar(cfg, now=None) -> tuple[Config, CalendarResult]`: returns cfg with calendar away periods appended to `away_periods` (skip one that duplicates or lies inside an existing config period; a calendar period overlapping-but-not-contained is kept as its own entry) and `markers` set.

## 7. Weekly recap — `recap.py`, `tests/test_recap.py`
- `weeks_available(df, cfg) -> list[date]` (Mondays of weeks intersecting `S..O`).
- `weekly_recap(df, cfg, week_start) -> Recap`: `start, end` (clipped to `S..O`), `complete` (all 7 days observed), `meals, me_swipes, dd_meals, snack_spend, snack_count, dd_spend, top_spot, top_spot_count, busiest_day (date, meals), zero_meal_days, prev_meals` (previous week or None), `pace_delta` (strict `me_left − target` as of week end, via `metrics.compute_metrics` on `dataclasses.replace(cfg, as_of=end)`, variant per `cfg.exclude_away`), `lines: list[str]` (3–5 short human sentences, e.g. "9 meals this week, 2 more than last week.", "3 at GH The Den.", "$14 on 3 snacks.", "10.4 meals ahead of an even pace.").

## 8. Habits — `habits.py`, `habits_charts.py`, `tests/test_habits.py`
- `hour_weekday_matrix(df, cfg) -> pd.DataFrame` 7 rows (Mon..Sun) × 24 hour columns, counts of meals (ME swipes net of reversals + DD meals) in the window `data_cutoff..O`.
- `streaks(df, cfg) -> Streaks`: longest run of consecutive days eating at the same place (place, length, start, end), longest run of days with ≥1 meal, longest gap with 0 meals (within `S..O`, away days excluded from gaps when on), current streak of days with a meal.
- `late_night(df, cfg) -> LateNight`: DD purchases and ME swipes between `late_night_start` and `late_night_end` (wraps midnight): count, DD dollars, top location, share of all DD spend.
- `place_stats(df, cfg) -> pd.DataFrame`: per place — swipes, DD $, visits, typical hour (median), favorite weekday.
- Charts: `heatmap_chart(matrix)`, `place_chart(place_stats)`.

## 9. Semester comparison — `compare.py`, `compare_charts.py`, `tests/test_compare.py`
Compare the current semester with each `cfg.history` semester using whatever the ledger holds (old semesters may have only some accounts and only partial date coverage — the export reaches back ~6 months). Ignores `data_cutoff`.
- `semester_summaries(df, cfg) -> list[SemesterSummary]` (history semesters then current, current window `S..O`): `name, start, end, covered_start, covered_end` (first/last transaction date inside the window; None if no data), `covered_days`, per pot `{used, per_day, per_week}` computed over covered days only (None when the pot has no rows), DD meal vs snack $ and counts, `top_places` (list of (place, amount/count)), `note` describing partial coverage in plain words.
- `weekly_usage(df, cfg) -> pd.DataFrame`: long format `semester, week (1-based from that semester's start), pot, amount` for overlaying semesters.
- Charts: `weekly_overlay_chart(weekly, pot)`, `per_day_comparison_chart(summaries)`.

## Integration (after all modules exist)
### Dashboard — `app.py`, `charts.py`, `tests/test_app.py`
- Entry point (`run()`): `apply_calendar` before the sidebar so calendar away periods appear in the sidebar's away list with their own toggles (labelled as from the calendar); show calendar warnings in the Data tab.
- New/changed tabs (keep the total ≤ 9; existing tabs stay): **Forecast** (weekday profile chart + table — the day-of-week view; ME and DD forecast charts with band; chance each pot lasts; likely run-out range; note which days are observed vs forecast), **Daily plan** (today/tomorrow line, next 14 days as a compact calendar strip/table, toggle exchanges-only vs with DD, spend-down sentence and numbers), **Habits** (heatmap, streaks, late-night, places, weekly recap with a week picker), **Compare** (semester summaries table with coverage notes, overlay + per-day charts).
- Calendar markers drawn on balance charts (thin labelled bands/lines).
- Escape `$` in any markdown text via the existing `esc()` helper.

### Tiles — `tiles.py`, `tests/test_tiles.py`
- `build_page_html(cfg, df, today)` is the only entry point `app.py` calls; keep that signature.
- Use the forecast for projections (verdict tile, "will hold"/"run out by" tiles show the likely range and the chance of lasting); add tiles for today's plan ("2 meals today · 1 tomorrow"), the spend-down sentence, weekly recap, weekday fact (biggest/smallest day of the week), habits (late-night spend, streak), semester comparison fact.
- **Live tiles**: a tile may carry a second face; it flips between faces on a timer, Windows 8-style, CSS-only (no JavaScript — `st.html` strips scripts), staggered so tiles don't flip in unison, paused on hover, disabled under `prefers-reduced-motion` (show the front face). Text must stay inside its tile at every size (see existing `.val.long` handling) and remain readable (white on the existing darkened palette).
